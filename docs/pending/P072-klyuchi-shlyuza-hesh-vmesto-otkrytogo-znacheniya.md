# 🔐 Ключи шлюза — хэш вместо открытого значения (MANDATE brain 2026-08-01, 🔴)

> Запись `P072` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-08-03 · snooze 0 · ✅ ЗАКРЫТО по ре-триаж 2026-09-09 — ни одного открытого маркера в теле секции, всё в прошедшем времени; тег `fresh` держался 37 дней на законченной работе` — **сделано и задеплоено целиком** (PR #426, #427).
На проде `secret` занулён, шлюз проверяет по хэшу; проверено живьём после каждого шага:
настоящий ключ → 200, произвольный → 401, health 200. Гоньба прошла через миграции, не
заметив их (605 вызовов, последний уже после зануления).

**Мандат:** `GatewayKey.secret` лежал в БД открытым текстом и сравнивался со значением —
компрометация дампа отдавала все ключи потребителей. У OIDC-клиентов хэш был, у шлюза нет.

- В БД теперь `secret_sha256` (по нему идёт проверка, поиск по индексу вместо перебора всех
  строк на каждом запросе) и `secret_prefix` — первые 6 символов для опознания человеком.
- **Почему sha256, а не scrypt как у паролей:** ключ — `secrets.token_urlsafe(32)`, 256 бит
  машинной энтропии (перебирать нечего), а проверка идёт на **каждом** запросе потребителя.
  Медленный KDF не добавил бы стойкости, но стоил бы задержки на всём трафике шлюза.
  Разбор — в докстринге `modules/gateway/keys.py`, чтобы следующий не «унифицировал».
- `get_effective_gateway_keys()` (словарь всех секретов в памяти) заменён на
  `resolve_gateway_key_name(presented)`. Семантика merge сохранена: БД главнее env,
  отключённый в БД ключ env не воскрешает, недоступная БД → env-fallback.
- Потребителей ре-выдача **не** затрагивает: их ключи не меняются, мы лишь перестаём хранить
  значение у себя. Потерянный ключ теперь нельзя подсмотреть — только ротировать.

**Развёртывание — три шага, порядок обязателен** (иначе окно 401 у потребителей):

1. ✅ **`074_gateway_keys_hash.sql`** — аддитивная, применена **до** рестарта: колонки +
   хэши из имеющихся значений (`UPDATE 6`, строк без хэша — 0). Старый код колонок не видит.
2. ✅ **рестарт с новым кодом** — проверка перешла на хэш, подтверждена живым запросом.
3. ✅ **`075_gateway_keys_drop_plaintext.sql`** — `UPDATE 6`, `secret` занулён у всех.
   Применена под гейтом #025 с подтверждением владельца.
4. 🟢 **`076`** (следующим релизом) — `DROP COLUMN secret`. Колонка держится занулённой один
   цикл, чтобы откат кода на предыдущий релиз не упёрся в отсутствующую колонку.

🛠 **Грабля миграции (PR #427):** в 075 `UPDATE ... SET secret = NULL` стоял **перед**
`ALTER COLUMN secret DROP NOT NULL` и упал на первой строке. Спас `ON_ERROR_STOP=1` — отбил
транзакцию целиком, данные не пострадали. Без него половина миграции легла бы молча.
**Правило:** `psql -v ON_ERROR_STOP=1` обязателен для любой миграции с несколькими стейтментами.

# ✅ HTTP-отказ шлюза ВК терял класс и доезжал до оператора тупиком (найдено 2026-09-07) — ЗАКРЫТО в тот же день

> Запись `P126` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-09-07 · snooze 0 · fresh · корень закрыт, два хвоста ниже`

**Что видел владелец.** Публикация заявки Аркадия Осетрова (`ad_requests.id=1139368`,
ЛЕБЯЖЬЕ-ИНФО) из «Реклама → Входящие заявки» упала надписью «Ошибка публикации: Публикация
не удалась: VK API error: Response code 502». Что делать дальше — из надписи не следовало.

**Что было на самом деле.** ВКонтакте лежал **полторы минуты** (07.09 11:03:53–11:04:26):
24 отказа 502/503/504 подряд на `wall.get`, `wall.post`, `upload_wall_photo`. После 11:04:26 —
ни одного. Клик владельца попал ровно в это окно.

**Состояние проверено чтением, а не выводом команды** (#218 — «502 не доказывает, что запись
не произошла»): пост `-170437443_21728` остался `post_type=suggest` в предложке, верх стены
чист, строка заявки `status=new`, `contacted_at` пуст. Публикация не состоялась целиком,
половинчатого состояния нет — повтор задвоить не мог.

**Корень — не 502, а потеря класса ошибки.** `vk_api.exceptions.ApiHttpError` наследует
`VkApiError`, а **не** `ApiError`, поэтому в `VKClient.api_call` пролетал мимо ветки, где
сохраняется код, и попадал в generic `except Exception` — наружу шёл голый текст без кода.
Дальше по цепочке всё сравнивает код: fallback на community-токен (15/27) и ротация
publish-кандидата (5/17/29). Ноль не совпадал ни с чем, и **до механизма устойчивости
управление не доходило вовсе**. Ровно тот же провал был на втором пути — `messages.send`
в `vk_actions.py` возвращал `error_code: 0`.

**Починено ([PR #673](https://github.com/Valstan/setka/pull/673)):**

- `ApiHttpError` ловится отдельной веткой и несёт `transient: True` + `http_status`.
  **Синтетического кода не выдумываем** — он утёк бы в `vk_error_code` отчётов и читался бы
  как настоящий ответ ВК (см. докстроку `_vk_error_code_of`);
- **чтения** повторяются молча (2 повтора, backoff 1.5 с) — allowlist по префиксу метода;
- **записи не повторяются молча никогда.** Это не недоделка: 5xx означает «шлюз не ответил»,
  и ответ мог потеряться уже после того, как ВК запись принял. Слепой повтор `wall.post` —
  ровно механизм, давший 27.08 один и тот же пост каждые полчаса в `@gonba_life`;
- оператор видит «ВКонтакте временно недоступен — попробуйте ещё раз через минуту. Заявка
  не тронута, задвоить публикацию нельзя» жёлтым, а не красное «Ошибка публикации».
  API отдаёт `503`, а не `502`;
- 25 тестов; на коде до починки красные — проверено подстановкой старых файлов.

**Оба хвоста дописаны в тот же день ([PR #674](https://github.com/Valstan/setka/pull/674)):**

- ✅ **Тройной префикс убран у обычного отказа.** Надпись собиралась из шести слоёв: `vk_api`
  → `vk_client` → `_invoke` → `VKPublishError` («VK API error: ») → `ad_cabinet.py`
  («Публикация не удалась: ») → `ad_cabinet.js` («Ошибка публикации: »). Теперь эндпойнт
  собирает одну фразу из уже разобранных полей (`_publish_failure_detail`), а фронт своего
  префикса не добавляет: «ВКонтакте отклонил публикацию (код 214). Access to adding post
  denied». **Строка исключения не тронута** — `str(VKPublishError)` остался
  `VK API error: [<код>] <текст>`, на него завязаны `extract_vk_error_code` (регулярка) и
  `error_message` в БД; инвариант закреплён тестом.
- ✅ **Отложенные публикации различают аварию и отказ.** На транзиторном отказе строка
  получает человеческое «ВКонтакте был временно недоступен — повторите раскладку, дата не
  занята», а ответ эндпойнта — флаг `vk_unavailable` (проходит и сквозь композицию С5).

  ⚠️ **Поправка к прежней записи этого пункта.** Здесь стояло «оставлять на повтор следующим
  тиком» — **такого тика не существует**: отложенные посты живут в собственной отложке ВК,
  celery-задачи, которая бы их дожимала, в проекте нет. Заводить её ради полутора минут
  аварии значит завести новый механизм с собственным риском дублей. Статус остаётся `failed`
  **сознательно**: только он выводит строку из-под уникума `uq_ad_sched_client_day_slot`
  (покрывает `pending`/`scheduled`/`published`), то есть повторная раскладка той же даты
  проходит, а не упирается в 409. Повторяет человек — ему и сказано словами.

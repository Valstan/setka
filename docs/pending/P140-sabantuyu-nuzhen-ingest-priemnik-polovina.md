# 🖐 Сабантую нужен ingest-приёмник — половина решения владельца не исполнима без соседа

> Запись `P140` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-09-14 · snooze 0 · parked · условие расконсервации: у сабантуй.вмалмыже.рф появится POST /api/ingest/posts и ключ SABANTUY_INGEST_KEY`

Уточнение владельца 14.09: «про сабантуй публиковать в сабантуй, про казанскую — в
казанскую, **мешать не надо**». У Сабантуя **свой сайт** (`сабантуй.вмалмыже.рф`,
есть в каталоге сервисов), и новости про него должны идти туда, а не на сайт ярмарки.

**Наша половина сделана** (PR #710): ловля по теме идёт по всему потоку района, сужение по
пабликам снято, слово «сабантуй» из ловли ярмарки убрано, чтобы потоки не смешивались.

**Вторая половина невозможна:** у сайта Сабантуя **нет ingest-приёмника** — проверено по их
репозиторию, в `web/src/app/api/` есть auth, push, ugc, revalidate, маршрута `ingest/posts`
нет ни одного (у Казанской для сравнения есть). Доставлять некуда, поэтому новости про
Сабантуй сейчас просто не отбираются.

Запрошено письмом [`2026-09-14-sabantuy-needs-an-ingest-endpoint…`](../../mailbox/to-brain/2026-09-14-sabantuy-needs-an-ingest-endpoint-owner-split-the-two-streams.md):
эндпойнт по общему контракту, ключ `SABANTUY_INGEST_KEY` в комнату, список рубрик.

**Когда приедет — работы на строку конфига:** механизм ловли по теме уже общий, третий сайт
описывается `ingest_url` + `key_env` + `sections` + `source_keywords: ("сабантуй", …)`.

⚠️ **Оговорка:** профильный ВК-паблик у двух праздников общий («САБАНТУЙ — КАЗАНСКАЯ — 2026 |
МАЛМЫЖ»), он пишет про оба вперемешку. Поэтому разводит **слово в тексте**, а не происхождение
поста — и именно поэтому он больше не отдаётся сайту ярмарки оптом. Пост, где есть и Сабантуй,
и ярмарка, по текущему правилу уедет на ярмарку.

**✅ Источник починен 2026-09-14 по решению владельца** («отлавливать такие новости, чтобы
сайт не выглядел умершим… включай в пул общий»), PR #709 и #710:

1. **«САБАНТУЙ — КАЗАНСКАЯ — 2026 | МАЛМЫЖ»** (`-213609985`, 775 подписчиков, город Малмыж)
   найден сканом и заведён в пул района `mi` категорией `kultura`; его `owner_id` добавлен
   в `source_owner_ids`.
2. **Ловля по словам во всём потоке района** — новое поле `source_keywords`, складывается с
   `source_owner_ids` по **ИЛИ**: пост берётся либо из профильного паблика (тогда слова не
   нужны), либо откуда угодно в районе, но со словом «сабантуй / казанская / ярмарк / ярмароч».

**Почему одного паблика было мало — замер, а не предположение.** Стена «Сабантуя»:
153 поста за два года, **все в мае–августе**, последний 03.08, и половина из них перепечатки
(губернатор, налоговые уведомления), а не про ярмарку. Без ловли по словам сайт жил бы два
месяца в году.

**Почему словами, а не «пустить весь район в модель».** Район даёт ~820 LLM-вызовов в месяц
(замер по журналу портала: 394 доставлено + 347 отклонено + 80 упало за 30 дней). Второй сайт
на том же потоке удвоил бы счёт ради нескольких материалов в год. Предикат по тексту не стоит
ни вызова модели, ни запроса к ВК.

Попутно правлены правила сайта: пункт 6 велел **отклонять** Сабантуй как «другой праздник» —
это прямо противоречило указанию владельца, Сабантуй из списка изъят.

**🟡 Осталось непонятым:** почему у живого ДК за 30 дней собран **один** пост. Механические
дропы (возраст/дедуп) в аудит не пишутся, поэтому из журнала причина не видна — нужен
отдельный прогон отбора с логом по этому `owner_id`. На ловлю по словам это не влияет, но
означает, что профильный паблик №1 в поток почти не попадает.

**Побочный вывод шире случая:** приём выдач — шаг деплоя, который **никто не выполняет
автоматически**, и его пропуск не виден ниоткуда, кроме ручного `--list`. Второй приёмник
конвейера простоял так с 02.09, а ключ публикации портала — двое суток. Кандидат в шаг
релизной памятки [`reliz`](../../.claude/commands/reliz.md).

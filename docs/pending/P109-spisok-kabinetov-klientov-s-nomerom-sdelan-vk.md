**Заказ (три части).** (1) Операторский список кабинетов: одна строка — один кабинет,
кликабельная, с **уникальным номером** (клиенты плодят дубли кабинетов: «проверяю один,
он сидит в другом»), с именем из ВК, если оно есть, и позже — счётчиками (заказано /
вышло / оплачено); сортировка по **последнему движению** в кабинете (чат, заказ, оплата).
(2) Владелец входит в любой кабинет без ограничений и действует от имени клиента.
(3) Для тех, кто не хочет выходить из ВК, — **бот-дублёр**: уведомления из кабинета в
личку ВК + кнопки на все действия кабинета (цены, баланс, заказ поста, запрос оплаты,
создание поста с текстом и картинками). Уведомления о движениях — владельцу в ВК и Telegram.

**Сделано 02.09 (часть 1, PR `feat/cabinet-list-numbered`).**
- Номер кабинета = `ad_clients.id`, второго нумератора нет намеренно (два номера у одного
  кабинета путают сильнее одного). Клиент видит «Кабинет №N» в шапке `/cabinet`, владелец —
  в списке и в `?as_client=N`; в разговоре достаточно спросить номер из шапки.
- `modules/ad_cabinet/cabinet_list.py` + `GET /api/ad-crm/cabinets` (`?all=1` — и
  CRM-клиенты без аккаунта). Имя — цепочка: имя карточки (при ВК-входе из профиля) →
  `display_name` аккаунта → логин → vk id → «Кабинет №N». Свежесть = max(чат любой стороны,
  действие клиента из журнала, решение владельца по посту, действие владельца от имени
  клиента, оплата, заведение). **Операторские правки карточки строку не двигают** — иначе
  массовая операция в CRM перетасует список.
- Вкладка «Кабинеты» в `/ad`: блок «Кабинеты» первым, строка → `/cabinet?as_client=N` в новой
  вкладке, справа счётчики «заказано · вышло · оплачено», бейдж непрочитанных, иконка →
  карточка CRM. Тесты `tests/test_ad_cabinet/test_cabinet_list.py` (настоящий SQL).

**Часть 3 — ВК-бот-дублёр: план, не начат.** Вся нижняя инфраструктура уже в проекте, это
не «с нуля»:
- приём сообщений сообществу — Bots Long Poll в `modules/radar/vk_intake.py` (Радиоточка,
  env `RADAR_VK_COMMUNITY_ID`, beat-тик); отправка в личку через community-токен —
  `modules/radar/delivery.py::_make_default_vk_dm_sender` и `modules/notifications/vk_actions.py::send_message`
  (там же `messages_allowed` — проверка, что пользователь разрешил сообщения сообществу);
- привязка «vk_id → кабинет» — уже есть: `ad_clients.radar_user_id → radar_users.vk_user_id`,
  а для клиентов из предложки — `ad_clients.author_vk_id`;
- все действия кабинета — уже функции, не UI: `client_orders.create_order` (заказ по районам,
  цена только сервером), `chat.post_message`, пакеты/баланс в `spend_balance`/`balance`,
  прайс `price-table`/`quote` в `web/api/advertiser_cabinet.py`.

Что строить (оценка — 2–3 сессии, отдельными PR):
1. **Исходящее (самое ценное и дешёвое):** `owner_ping`-подобный `client_ping` — событие кабинета
   (одобрено / отклонено с причиной / вышло / ждём оплату / ответ владельца в чате) → личка ВК
   клиента через community-токен, если `messages_allowed`; иначе молча. Плюс зеркало
   владельцу в ВК (сейчас пинги только в Telegram — `owner_ping._send_telegram`).
2. **Входящее:** отдельный Long Poll-обработчик (или тот же тик Радиоточки с диспетчером по
   сообществу) → машина состояний диалога в Redis (`vkbot:{peer}` → шаг + черновик) → клавиатура
   VK (`keyboard` в `messages.send`, payload-кнопки). Меню: 💰 Баланс · 📋 Цены · 🛒 Заказать
   пост (текст → фото → районы → дата → подтверждение → `create_order`) · 💳 Запросить оплату ·
   💬 Написать (→ `chat.post_message`, ответ владельца — назад в личку).
3. **Фото из ВК** — приходят как attachments с URL, качать и класть в `photos` кабинета тем же
   путём, что `POST /api/advertiser/photos`.

**Три решения владельца — приняты 2026-09-02 (вечер), бот можно начинать:**
- **Лицо бота — сообщество «САРАФАН»** (не Радиоточка): «нативнее и понятнее клиентам».
  Нужен community-токен САРАФАНа с правом `messages` и включённые сообщения сообщества;
  Long Poll — отдельный обработчик, не тик Радиоточки.
- **Заводить кабинет автоматически** при первом сообщении боту от незнакомого `from_id`
  («цеплять всех, лишних потом руками удалю»). Один vk_id → одна карточка, дубли реже.
- **Уведомления владельцу — на аккаунт Valstan** (личка от имени САРАФАНа; владелец
  разрешает сообщения сообществу сам). Telegram-пинги остаются как есть.

Порядок работ: (1) исходящие уведомления клиенту и владельцу в ВК → (2) меню-клавиатура и
машина состояний диалога → (3) заказ поста с фото из ВК.

# 📊 Воронка фильтра, прогресс оператора и аранжированная лента (заказ владельца 2026-08-19, вечер)

> Запись `P085` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-08-19 · snooze 0 · fresh · ✅ задеплоено (#492 + #493), проверено на живых данных`

Три жалобы владельца: непонятно, фильтрует ли сеть свежее; нет сквозной картины
«собрано → опубликовано»; лента разбирается поштучно и медленно.

**Половина постановки снялась замером.** Свежее сеть уже фильтрует: `prepublish`
включили в 14:51 того же дня, и покрытие свежего скакнуло с 5-17% (дни аварии
16-18.08) до **73.8%**. «7000 собрано / 1300 размечено» — это окно свежести в
3 суток, куда попали дни трёхсуточного молчания движка, а не хроническое
отставание. Порядок выборки в `fetch_pending` тоже уже верный (свежие первыми,
кандидаты впереди отсеянных) — переделывать было нечего.

**Сделано (этот PR):**

- `funnel_stats` — воронка за сутки: собрано → размечено → допустил/выкинул/отложил
  → **дошло до читателя** (join с `bulletin_curation_runs`, где
  `published_post_id IS NOT NULL`). Отсев дублями сознательно не показан: аудит
  идемпотентен по `lip`, честной цифры в базе нет.
- `operator_progress_stats` — «движок 1960 · вы разобрали 447 · осталось 1742 ·
  темп 62/ч · разгрести ~28 ч». Темп по `classification_corrections`, **не** по
  `reviewed_at`: архивация 18.08 проставила его 44 177 постам одним `UPDATE`.
- `review_feed_grouped` — блоки «вердикт × тема», внутри дословные дубли схлопнуты
  в карточку `×N`; `bulk_agree` / `bulk_correct` закрывают группу одним нажатием.
- Окно свежести: дефолт `CLASSIFIER_SOURCE_DAYS` 3 → **1** («жить только свежим»,
  решение владельца). На проде переменная не выставлена — дефолт подействует сам.

**Проверка на проде сразу после деплоя вскрыла три «цифры-обещания» — все свои**
(починены в #493, и это главный урок захода):

1. **«В публикацию» считала один район из 29.** Журнал курации ведётся только по
   `mi` (18 свод­ок за сутки), а сбор идёт по 29 — число читалось как результат по
   сети. Теперь рядом с ним стоит охват.
2. **«Токенов: 0»** — `tokens_estimate` пуст у 2238 вердиктов из 2238, его никто не
   заполняет. Строка убрана: ноль на панели человек читает как «не потратил», хотя
   за те же сутки ушло ~1.4 млн (видно в логах `prepublish`).
3. **Блоки считали 500 постов из 2020** — счётчики строились по обрезанной выборке.
   Теперь расчёт по всей очереди, `cards_per_block` ограничивает только рисование.

**Замер после починки:** очередь 2020 постов схлопнулась в **24 блока**, покрытие
полное (mismatch 0). Воронка: собрано 2957 → размечено 1842 (62.3%) → допустил 1409 ·
выкинул 822 · отложил 7. Прогресс: движок 2238, оператор 219, темп 9.1/ч,
отставание ~222 ч — это и есть довод за пакетный разбор.

**Открытые хвосты:**

- ⏳ **Живьём в браузере не смотрено** — всё покрыто тестами и проверено запросами к
  боевой БД, но глазами владельца на странице не проверялось.
- 🟡 **Связь «пост → публикация» доступна только по одному району.** Журнал курации
  `bulletin_curation_runs` пишется для `mi`; `scheduled_publications` за сутки пуст,
  `work_tables` — дедуп-стор без времени. Чтобы «дошло до читателя» стало цифрой по
  сети, журнал нужно вести по всем активным районам. Пока — подписано охватом.
- 🟡 **Похожесть только дословная.** Внутри показанных карточек схлопывание экономит
  ~189 нажатий; основной выигрыш даёт не оно, а блоки. Нечёткая похожесть («одна
  новость, пересказанная разными пабликами») отложена: на завале за 40 дней дубли
  давали 49%, на суточной очереди — вчетверо меньше, и цена реализации выше выигрыша,
  пока блоки не обкатаны.
- 🟡 **Покрытие 62.3% против 73.8% вчерашних** — окно сузилось до суток и захватило
  ночь, когда `prepublish` ещё не работал. Должно подрасти само; если через сутки не
  подросло — смотреть отдельно.

# ~~🎲 Случайная пачка на проверку — все районы, одна случайная тема (заказ владельца 2026-08-20)~~ ЗАКРЫТО 2026-08-28 — код в main и на проде

> Запись `P089` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-08-20 · snooze 0 · ✅ ЗАКРЫТО 2026-08-28 по ре-триажу — тег «ждёт релиза» был ложным: d1a8924 «feat(classifier): random review batch — all regions, one random theme (#503)» в main, web/api/classifier_review.py:277 GET /feed/random → service.review_feed_random (modules/classifier/service.py:1310), прод на 28b2a27`

Очередь сверху вниз держала оператора в одном пласте: свежие вердикты одной темы вытесняют
остальные, завал в других темах не виден. На этом уже напоролась дистилляция 2026-08-18 —
«мерили покойника», потому что сырьё приходило из одного угла потока.

**Что сделано:** `GET /feed/random` + `service.review_feed_random` — случайный пул непроверенных
вердиктов по ВСЕМ районам, из него случайно выбирается одна тема (равновероятно среди
присутствующих, а не пропорционально объёму — иначе «мусор» выпадал бы всегда), из неё до 10
случайных постов. Дословные дубли схлопываются, как в блочной ленте. Форма ответа — тот же блок,
что у `/feed/grouped`, поэтому групповые кнопки работают тем же кодом. На панели — переключатель
«случайная пачка» (**включён по умолчанию**) и кнопка «🎲 Дать ещё 10 постов на проверку»
(зеленеет, когда пачка разобрана). `exclude` не даёт кнопке возвращать пропущенное по кругу.

**Тонкость режима:** после группового действия лента НЕ перечитывается целиком (как в обычном
режиме) — иначе недоразобранная пачка сменилась бы новой темой на полпути. Закрытые карточки
удаляются точечно, новая пачка приходит только по кнопке.

# 🟡 Сторож ленты слеп к региону — `mark_published(topic)` без региона (найдено 2026-08-21, выделено из P091)

> Запись `P169` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-09-21 · snooze 0 · fresh · код не менялся с находки; лечение — ключ по (регион, тема) + порог по слотам региона`

Найдено в разборе [P091](P091-gotovnost-k-shagu-3-razbor-2026-08-21-ne-vhodit.md) п.4, выделено при
ре-триаже 21.09, чтобы не гнить внутри `parked`-записи.

**Симптом.** `bulletin_heartbeat.mark_published(topic)` ([`modules/bulletin_heartbeat.py:69`](../../modules/bulletin_heartbeat.py))
ключуется **только темой** — Redis-ключ `setka:digest_last_published:<topic>`. Пока хоть один регион
публикует `novost`, сторож рапортует `fresh`. 20–21.08 Арбаж и Подосиновец за сутки не выпустили ни
одной сводки из 6 слотов — сторож не покраснел ни разу. Сторож, который не может покраснеть на
случившемся отказе, — не сторож.

**Проверено 2026-09-21:** сигнатура та же, последняя правка файла — #617 (повторы Telegram), не по теме.

**Лечение (дёшево):**
- писать второй ключ `setka:digest_last_published:<region>:<topic>` из той же точки `track_digest_published`
  (старый ключ оставить — на нём дашборд `/api/monitoring/heartbeat` и алёрт);
- порог протухания — не 6 ч глобально, а по расписанию региона: «пропущено N слотов подряд»
  (у тонких районов 1–2 слота в сутки, глобальные 6 ч дадут ложный красный);
- алёрт — один список «регионы без `novost` дольше своего порога», с cooldown, как у текущего.

**Не делать:** чинить через сумму `отобрано=` из лога — счётчики считают волновые слоты, не посты
(P091 п.5); мерить надо по разным `lip` в `work_table`.

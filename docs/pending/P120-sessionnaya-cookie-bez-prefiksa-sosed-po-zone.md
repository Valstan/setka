# 🟡 Сессионная cookie без префикса `__Host-` — сосед по зоне может подбросить свою (#285, recommend brain 2026-09-05)

> Запись `P120` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-09-06 · snooze 0 · fresh`

**Мы в классе.** Кука зовётся `setka_session` (`modules/radar/auth.py:35`) и выставляется
**с `Domain=.вмалмыже.рф`** (`SESSION_COOKIE_DOMAIN`, `web/api/auth.py:65`) — ровно та
конфигурация, про которую предупреждает КАРМАН: любой хост под зоной вправе поставить куку
с тем же именем, и при двух одноимённых побеждает подброшенная.

**Но рецепт письма нам не подходит, и это не отговорка.** `__Host-` по определению
**запрещает атрибут `Domain`** — кука обязана быть host-only. У нас на `Domain` держится
единый вход: приложение одно, живёт на `вход.` / `радар.` / `сарафан.`, и сессия обязана
переезжать между поддоменами. Host-only это ломает — уже проходили на OAuth-state куке
(`web/api/radar_id.py:255`): без расширения домена первая попытка входа после каждого
выхода падала в «state не совпал», больнее всего по ВК-only аккаунтам без пароля.
`__Secure-` формально совместим с `Domain`, но дыру не закрывает: сосед подбросит
`__Secure-setka_session` ровно так же.

**Радиус.** Значение куки — подписанный токен (`verify_session_token`), поэтому подброс не
даёт **подделать** сессию, только **подменить** её на чужую-валидную. Для чтения это
обратимая путаница. Необратимое действие у нас есть — привязка `vk_user_id` к ряду при
ВК-входе. Но подбросить куку может лишь тот, кто уже держит хост под `вмалмыже.рф`, а все
соседи по зоне — сервисы самой экосистемы: это «скомпрометированный сосед», а не «любой в
интернете».

**Направление (не переименование):** привязать необратимое действие к личности, которую
сосед подделать не может — переспрос личности перед привязкой ВК и сверка `sub`. Это
проектирование, а не проверка на минуту; между делом не делать.

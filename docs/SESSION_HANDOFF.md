## Failed approaches (этой нитки)

- **Оценивать выигрыш батчинга по предельному размеру батча.** Обещал владельцу «в 25 раз»
  (батч на 20-25 стен), получилось **~6 раз**: волны в среднем по 13,6 групп, а мелкие волны
  (1-3 группы) всё равно стоят один запрос. **Считать по распределению размеров волн, а не по
  потолку батча.**
- **Отдать чтение community-токенам.** Проба на живом `COMM_166980909`: `wall.get` по своему
  сообществу, по чужому и `wall.getById` — все три `ERROR 27: method is unavailable with group
  auth`. Групповой токен не читает стены вообще. **Не пытаться повторно** — это ограничение ВК.
- **Положить новый `vk_client.py` на прод «на минутку» ради пробы.** Начал и остановился:
  это правка прод-файла вне релиза. Проба переписана автономной — свой VKScript, свой HTTP,
  ноль изменений на боксе. **Пробу пишут так, чтобы она ничего не трогала.**

## Открытые вопросы для пользователя

- 🟢 **Кэшировать ли чтение собственной стены района?** Замерено: 17 волн → 15 `wall.get`, это
  весь остаток расхода после батчинга (`parsing_scheduler_tasks.py:275`, 100 постов своей группы
  каждую волну). Своя стена меняется 2-10 раз в сутки, а читается каждую волну — кэш с
  инвалидацией по публикации дал бы ~10× суммарно вместо нынешних ~6×. **Не сделал сам: это
  дедуп-страховка, а не просто расход.**
- **Проверить `/tokens` завтра** — там будет честная цифра расхода за полные сутки с батчингом
  (ожидание ~300 на токен вместо ~1860).
- 🔴 **Чинить ли слепоту gitleaks** (правила под telegram смешанного регистра и `vk1.a.…`) —
  меняет то, что CI блокирует на мерже, поэтому не завёл сам.
- 🔴 **Ротация токена `COMM_137760500`** (owner-only) + чистка старых логов.
- **`VK_RATE_LIMIT_BACKEND=redis`** на проде не выставлена: кросс-процессный лимит ВК не работает.
- Хвосты прошлых сессий: журнал курации ведётся только по `mi`; названия регионов в БД отстали
  от ВК; батч №4 (подписать МАМУ на три группы); `GROQ_API_KEY` отозвать; кириллические redirect
  URL в кабинете ВК удалить.

## Не забыть (low-priority)

- 🛠 **Проба гейта/DSL проверяется тем, кто её исполняет.** Тесты с фейковым клиентом не видят
  синтаксис VKScript в принципе — как не видели затенение маршрутов (#496). Перед релизом
  VKScript прогнан на живом ВК: 6 групп одним запросом, сопоставление 6/6.
- 🛠 **Миграции на проде — от `postgres`, не от `setka_user`** (`sudo -u postgres psql -d setka -f …`);
  `DATABASE_URL` содержит `postgresql+asyncpg://`, psql её не понимает.
- 🛠 **JS в шаблонах не покрыт ничем** — проверять `node --check` на вырезанном `<script>`.
- 🛠 **`PRE_COMMIT_HOME` обязателен для `git commit`**, а не только для `pre-commit run`.
- 🛠 **Bash-heredoc падает «unexpected EOF» на backticks/кавычках** — многострочный код писать файлом.
- 🛠 **Ad-hoc скрипты начинают с `import database.models`**; `VKToken` живёт в `database/models.py`,
  а не в `models_extended.py`.
- 🛠 **Прод-скрипты требуют env явно:** `sudo bash -c 'set -a; . /etc/setka/setka.env; set +a; …'`.
- 🛠 **Локальный `pytest`** — `--basetemp=<scratchpad>/pt -p no:cacheprovider`.
- 🛠 **Прод: `now()` в psql — MSK, а `created_at` пишется наивным UTC.**
- 🛠 **Не-ASCII на прод — только файлом** (`scp`), никогда аргументом команды (G235).
- 🟡 **`VK token is invalid or expired` для группы `-218877712`** — токена с таким `community_id`
  в таблице нет вовсе; никто не смотрел.

## Failed approaches (этой нитки)

- **Workflow и субагенты в этой среде.** Два workflow 11.09 (диагноз «Failed to fetch», ранбук
  Татарстана) не вернули ни одного результата: агенты падали с `403 Request not allowed` — 41 старт,
  0 результатов, около 1,9 млн токенов впустую. Пока авторизация субагентов не починена — работать в
  главном цикле; прежде чем запускать новый, заглянуть в `journal.jsonl` первого прогона.
- **Долгий прогон на проде в foreground-SSH.** `--apply` оборвался по `Connection reset by peer`
  посреди вывода; процесс на боксе доработал, но состояние пришлось восстанавливать аудитом и
  журналом. Длинное — `nohup … > /tmp/x.log 2>&1 &` и ожидатель по логу.
- **`wall.get` ключом сообщества** — `[27] method is unavailable with group auth`. Что применилось
  при оформлении, смотреть в журнале `promo_group_setup` (`applied_fields`, `pinned_post_url`).
- **Экранировать регулярку внутри SQL-строки.** `[.` в классе символов Postgres читает как начало
  collating-элемента — «brackets [] not balanced». Шаблон собирать в Python (`mention_pattern`).
- **Верить молчанию `gh pr merge`.** В неинтерактивном режиме успешный мерж может ничего не
  напечатать, а `gh` к `api.github.com` с этой машины периодически падает по таймауту. Состояние —
  `gh pr view N --json state`, создание PR — повторять.
- **Считать «Failed to fetch» ошибкой сервера.** Сначала access-лог nginx: нет строки запроса —
  ищем на стороне клиента (11.09 с этой машины весь день рвались соединения к GitHub и к боксу).

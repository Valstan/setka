## Failed approaches (этой нитки)

- **Grant в КАРМАНе машиной — невозможно.** `createGrant` — server action под сессией владельца
  комнаты с `mfa:true`; room-токен и provisioning-ключ права не имеют намеренно. Выдавать — из
  браузера владельца (управляемая вкладка; в аудите запись идёт от `owner:1`). Мозгу предложен
  grant-endpoint под токеном комнаты-источника.
- **`list_gateway_keys.py` / `issue_gateway_key.py` без env не стартуют** (`DATABASE_URL is
  required`), а `/etc/setka/*.env` root-only. Рабочая форма:
  `sudo bash -c 'set -a; . /etc/setka/setka.env; . /etc/setka/secrets-token.env; set +a; cd ~/SETKA && venv/bin/python scripts/…'`.
- **`--owner-ids <список>` не работает**, когда список начинается с отрицательного id — только `--owner-ids=<список>`;
  `+420841463` привязка отвергает — голые цифры. Дополнение привязки — тем же скриптом без
  `--rotate` → `action: rebound`, секрет цел.
- **Приёмка ключом потребителя без печати секрета:** значение берётся из комнаты `setka` по
  `SECRETS_TOKEN` прямо в память python-процесса (stdin-скрипт через ssh), наружу — только статусы.
- **Логи прода частично root-only** (`nginx_*`): `grep` по `logs/*.log` без sudo падает на
  PermissionError — брать `sudo` или сужать glob до `celery-worker.log*`.
- **VPN `happ-tun` режет SSH** — «Connection timed out» на первом соединении, повтор помогает
  (в сессии срабатывало четыре раза).
- **Планировать аватар как «одну заливку» — недосчитать втрое** (4 вызова × до 3 попыток).
- **Правка `black_id` под агрегаторов — НЕ ДЕЛАТЬ**; **план «пауза пути + блок стены» для кодов ВК —
  НЕ КАТИТЬ** в прежнем виде (подробности в PENDING).

## Текущая нитка

_Нет — заказ владельца выполнен целиком, открытая стартовая позиция._

Сессия 2026-08-02 (3 PR: #421, #422, #423) — вся про домены и доступ. Начиналась с «дайте
покупателям рекламы человеческий адрес», закончилась починкой живого отказа Радара.

**Что изменилось в устройстве прода** (детали — новая [`docs/ops/HOSTS.md`](ops/HOSTS.md) и
секции ⏳ в [`PENDING_FOLLOWUPS.md`](PENDING_FOLLOWUPS.md)):

- **Сайт САРАФАНА виден только владельцу.** Роль `operator` больше не пропуск — решает личность
  аккаунта (`_is_owner`: логин **при роли operator** либо `vk_user_id`). Работают оба входа
  владельца: пароль (`valstan`, id 1) и ВК (id 2, `vk_user_id=20002978`, роль `radar`). Публична
  ровно одна ссылка — `/regions/links`, **точным** совпадением пути.
- **Все поддомены `вмалмыже.рф` — на https.** Схему знает только `X-Forwarded-Proto` от edge Джино
  (`$scheme` на боксе всегда «http»), редирект ограничен GET/HEAD. До этого вход по голому http
  **молча не работал**: сессионная кука `Secure`.
- **Радар был сломан неделю** — петля `/` → `/radar` → `/` у всех, кто вошёл: nginx дублировал
  решение приложения о том, где живёт интерфейс. Аноним петли не видел, поэтому её не замечали.
- **Конфиги nginx сведены в git** (`config/nginx_*.conf`). Лежавший там `setka.conf` был годичной
  давности, без TLS — установка из репо сняла бы HTTPS с техдомена.

Тестов **2016** (было 1991).

## Открытые вопросы для пользователя

- **Оба аккаунта владельца открывают сайт** (парольный `valstan` и ВК-личность). Если нужно пускать
  только парольный — `SETKA_OWNER_VK_IDS=0` в `/etc/setka/setka.env` + рестарт.
- **Непрочитанная почта brain: 4 директивы**, из них одна `high MANDATE` (ADR-0012 + 🔴 ключи шлюза).
  Обработка ждёт вашего «ок» — `/start` их доложил, но автоматически не применял.
- **Соседи с `http://вход.вмалмыже.рф`** в конфиге теперь получат 301 на GET-дверях. В нашем репо
  таких строк нет; если кто-то пожалуется — лечение у него (перейти на https), не откат.

  на лендинге сверить с реальностью; смоук-аккаунт `smoke_esa` жив (удаление — гейт #025);

## Не забыть (low-priority)

- 🛠 **Петлю редиректов ищут через nginx, а не мимо него.** Прямой запрос на `127.0.0.1:8000`
  её не воспроизводит вовсе — половина маршрута живёт в конфиге прокси. И проверять надо
  **с живой сессией**: аноним уходит на страницу входа на первом же шаге и петли не видит.
- 🛠 **Голый http прячет целый класс дефектов.** Service Worker и Push живут только в secure
  context: на http браузер молча отклоняет регистрацию. Три дефекта PWA/ВК-входа этой сессии
  были невидимы именно поэтому. Правишь то, что «и так не работало», — проверь, не было ли оно
  просто спрятано.
- 🛠 **Асимметрия пустых env:** `SARAFAN_CANONICAL_HOST=""` **выключает** правило домена, а
  `SETKA_OWNER_LOGINS=""` = «не задано» → дефолт (пустая переменная не должна оставлять сайт
  без владельцев).
- 🛠 **Карта `$setka_needs_https` — только для доменов за edge Джино.** На техдомене и
  `default_server` заголовка нет, карта даст 0 и редирект тихо пропадёт; там своё условие.
- 🛠 **Локальный `pytest` без `--basetemp` в писчий каталог** даёт 67 ошибок прав на `C:\Temp`
  (песочница). Прогон: `--basetemp=<scratchpad>/pt -p no:cacheprovider`.
- 🛠 `pre-commit` на этой машине падает с `InvalidManifestError`, пока не задан
  `PRE_COMMIT_HOME` в писчий каталог — кэш в `C:\Users\…\.cache` песочнице недоступен.
- 🛠 SSH и `gh` периодически флапают (TLS handshake timeout) — ретраить, не диагностировать.
  В этой сессии словили полный обрыв интернета посреди мержа; помог цикл ретраев.
- 🟡 У Кикнура доля отсева 43% и почти вся рекламная — глянуть источники при освежении.
- 🟡 Ротация `CLASSIFIER_INGEST_KEY` — только вместе с владельцем.
- 🟢 Каталог сервисов ждёт ТАКСИ; карточка портфолио появится обычным путём онбординга.

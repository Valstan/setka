## Следующий шаг

**Порядок жёсткий — рейтинг ДО встраивания**, иначе отбирать будет не из чего.

1. **Метрики и рейтинг** (не начато). Миграция: колонки `views`/`likes`/`comments`/`reposts` +
   `published_at` в `collected_post_audit` (их там сейчас нет вообще). Таска обновления метрик по
   правилам владельца: **не трогать посты старше 72 часов** и **не трогать уже опубликованные**.
   Затем отбор топ-N по рейтингу внутри разрешённых вердиктом.
2. **Квота разносола — часть звена 5, а не отдельная хотелка.** Владелец подтвердил 18.08, что
   научпоп и полезные советы вносит в ленты намеренно, **2-3 поста в сутки, не больше**.
   Утверждённое правило велит движку публиковать такой контент, но суточная норма правилом
   невыразима — классификатор судит пост по одному. Пока звено 5 не встроено, риска нет
   (вердикты классификатора публикацию не трогают, конвейер идёт алгоритмическим путём);
   **в момент включения звена 5 без квоты научпоп польётся в сводки без ограничений.**
3. **Встраивание отбора в парсер.** `modules/vk_monitor/advanced_parser.py`: принять
   `allowed_lips` + флаг `verdict_mode`. Классификация стадий `_filter_post` уже сделана —
   отключить редакционные (`hard_spam` :474, `neighbor_bulletin` :481, `advertisement` :484,
   `blacklist_text` :491, `region_words` :498, `no_attachments` :525, тематические :532),
   сохранить механику (возраст 72ч :440, дедуп по lip :449, чёрный список сообществ :462,
   дедуп по медиа :537 и тексту :551). Вызвать `selection.decide_mode` в
   [parsing_scheduler_tasks.py:292](../tasks/parsing_scheduler_tasks.py:292) и
   [cascaded_bulletin.py:456](../modules/cascaded_bulletin.py:456). Гейт — env-флаг, по умолчанию выключен.
4. **Посты без текста.** ИИ-фильтр должен ставить им явный `hold` с пометкой «нет текста, вложения
   не читаются». Сейчас `headless.classify_posts` их пропускает (`skipped_no_text`).

## Failed approaches (этой нитки)

- **Чеканить правила из завала, не разделив его по `source`** — так и сделал, и ошибся. Вывод
  «`hold` — 25.9% потока, сеть отказывается решать» оказался про облачную рутину, выключенную
  12.08; у живого движка `hold` = 0.4%, расхождение на одинаковом входе 4.5% против 34.9%.
  Правило-гейт под это утверждено и работает вхолостую. **Всегда делить накопленное по движку
  ДО обобщения.**
- **Считать раскол вердиктов признаком дыры в правиле** — для темы «объявления» (838 delete
  против 744 publish) это оказалась работающая предметная градация, а не шум. Проверять
  измерением (дубли текста), а не глазом.
- **Просто отправить в retire правило, которое «замещено» новым** — предложил для id 20 и был
  неправ: оно несёт три пункта, новое покрывает один. Простой retire снёс бы «область в целом →
  publish» и «криминал чужого района → delete». **Перечитывать правило целиком перед retire.**
- **Кластеризовать завал нейросетью** (было предложено как основной подход) — отвергнуто
  владельцем: DeepSeek занимается фильтрацией потока, а разбор его вердиктов делаем мы в чате.
- **Считать качество headless по проценту совпадения с рутиной** — отвергнуто ранее: процент
  совпадения с неэталоном не измеряет качество.

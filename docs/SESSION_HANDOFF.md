## Failed approaches (этой нитки)

- **`celery -A tasks.celery_app inspect scheduled` для проверки beat-расписания** — слепа по
  построению: опрашивает таймер ВОРКЕРА (ETA/countdown), beat на control-канал не отвечает;
  «логи beat» печатают расписание только на debug. Вернула бы пустоту при любом исходе деплоя.
  **Работает:** пара — python-пробник `beat_schedule` на боксе **с подставным ключом**
  (доказывает, что умеет краснеть) + `celery inspect registered | grep <task>`.
- **Длинная ssh-команда «restart && is-active»** — `Connection reset` съел рестарт, сервисы
  остались `active` со старым кодом в памяти; `is-active` про это молчит. **Работает:**
  короткие команды + проверка эффекта по `systemctl show -p ActiveEnterTimestamp`; при
  троттлинге sshd (`Connection reset` → `timed out`) паузы 40–120 с.
- **Фоновые Explore/Plan-агенты в этой среде стопорились** (3 из 4, «no progress 600s») —
  разведку добирал прямыми чтениями; Plan-агент со второй попытки дошёл и его уточнения
  влиты в план (статусы `pending|rejected` в той же колонке, `order_ref`, «сразу» = отложка
  +3 мин, фото вне `/static`).
- **BigInteger PK на sqlite не автоинкрементится** — in-memory-тесты падали `NOT NULL id`.
  **Работает:** `BigInteger().with_variant(Integer, "sqlite")` — паттерн уже жил в
  `models_extended.py:491`, применён к Ad-таблицам (Postgres DDL не меняется).
- Перенесено из прошлых сессий, всё ещё в силе: «зелёный прогон гейта» ≠ доказательство
  отсутствия — сперва показать, что умеет краснеть; проверка, чей ответ не меняется при
  подмене предмета, — не проверка; строить проверку копированием правки нельзя.

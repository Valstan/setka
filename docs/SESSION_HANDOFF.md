## Failed approaches (этой нитки)

- 🔴 **Читать `collection audit: recorded 0` как «постов не было».** Ранний `return` стоял до
  логгера: строка печаталась только когда посты **были**, но уже записаны. На этой инверсии
  построен и снят первый диагноз по Подосиновцу. Прибор починен в `fbbcf5c`, но привычка чтения
  опаснее кода — в журнале до выката ещё есть старые строки.
- 🔴 **Сравнивать районы по `collected_post_audit`.** `lip` уникален глобально, дедуп без
  предиката на регион и тему: пост пишется один раз в жизни, на ту пару (регион, тема), чья волна
  увидела его первой во всей сети. Объём сбора мерить **только** по `parsing_stats.total_posts_scanned`.
- 🔴 **Строить интеграцию с провайдером, не проверив существующий контур.** Облачная рутина была
  задокументирована и отвечала 200 — агент вместо неё спроектировал адаптер на Anthropic API под
  ключ, которого нет. **Правило:** грепнуть репо и `docs/ops/`, затем **дёрнуть** найденное; по
  тексту выключенный контур неотличим от исторической справки.
- 🔴 **«Celery по SIGTERM гасится тёпло»** — сказано как факт, опровергнуто журналом: рестарт 14:00
  дал `WorkerLostError: signal 15`, задача `poll_radar_sources` погибла. Перед рестартом ждать
  пустой очереди (`redis-cli llen celery` + `inspect active`), как сделано в 14:35 — там чисто.
- 🔴 **Голый `./venv/bin/python -c` на проде не видит секретов** — `DATABASE_URL`/`REDIS_URL` живут
  в окружении systemd. Читать БД через `sudo -u postgres psql`, пайплайн — через celery
  (`scripts/smoke_test.py`).
- 🔴 **`temperature` в Anthropic SDK 1.7.0** — параметра у `messages.create` нет вовсе и `**kwargs`
  тоже; передача падает `TypeError` до сети. Не относится к текущему коду (PR закрыт), но если
  когда-нибудь вернёмся — сверять форму с установленным пакетом, а не с памятью.

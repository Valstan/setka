## Failed approaches (этой нитки)

Все четыре — свои, найдены прогоном по боевым данным уже **после** зелёных тестов и деплоя.
Общее у них одно: **тест кормит функцию данными, которые сам же создал**, и свойство «в проде
источник покрывает не всё» на выдуманных данных невыразимо.

- **Показывать число без охвата его источника** — «дошло до читателя: 22» бралось из журнала
  курации, который ведётся по **одному району из 29**. Число верное, подпись врёт. Починено в
  `d7eb8af`: рядом стоит охват. **Правило: у каждой цифры на панели спрашивать не значение, а
  какую долю реальности покрывает её источник.**
- **Показывать поле, которое никто не заполняет** — `tokens_estimate` пуст у 2238 вердиктов из
  2238, панель рисовала «токенов: 0» там, где ушло ~1.4 млн. Строку убрал совсем.
  **Отсутствующая метрика честнее неполной:** пустое место читается как «не измеряем», а ноль —
  как «не потратил».
- **Строить счётчики по обрезанной выборке** — группировка брала 500 постов из 2020 и по ним же
  считала заголовки блоков. Теперь `limit` ограничивает расчёт, `cards_per_block` — только
  рисование, а `total`/`ids` полные.
- **Считать темп оператора по `reviewed_at`** — отвергнуто до реализации: архивация завала
  18.08 проставила его 44 177 постам одним `UPDATE`, и отставание вышло бы нулевым при нуле
  разобранного. Считаем по `classification_corrections`; регресс-тест на это есть.

- 🛠 **JS в шаблонах не покрыт ничем** — синтаксическую ошибку не ловят ни pytest, ни pre-commit,

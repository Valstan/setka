# Отбор по вердиктам + сортировка по рейтингу (звено 5, шаг 2)

**Дата:** 2026-08-20
**Заказ:** владелец («да начинай» после выбора `alpha` по витрине)
**Статус:** одобрено владельцем, к реализации
**Предыдущий шаг:** [2026-08-19-post-metrics-and-rating-design.md](2026-08-19-post-metrics-and-rating-design.md)

## Контекст

Шаг 1 завёл метрики и витрину; владелец исследовал `alpha` на 1078 измеренных
кандидатах 28 районов и выбрал **0.25** (совпало с дефолтом кода —
`RATING_VIEWS_ALPHA` на проде не выставляется). Блокер снят, начинается шаг 2:
**отбор в сводку внутри разрешённых вердиктом, с верхушки рейтинга.**

Редакционные фильтры НЕ снимаются — это шаг 3, и `hard_spam` не снимается
вместе с остальными (G151).

## Что меняется

### A. Сортировка сводки: `post_popularity` → `post_rating(alpha)`

`BulletinBuilder._sort_by_popularity` переводится с жёсткой `post_popularity`
(= `alpha 0.5`) на `post_rating` с `alpha` из конфига
(`config.classifier.get_rating_views_alpha`, дефолт 0.25 — выбор владельца).

- Пост без `views` → `score = None` → хвост очереди (не ноль и не верхушка —
  та же семантика, что в витрине). Раньше отсутствующие просмотры считались
  нулём, и делитель схлопывался в 1 — пост без единого просмотра мог обогнать
  районный хит.
- Гейта нет: это ровно та ручка, ради которой строилась витрина, и она уже
  выбрана. Откат = `RATING_VIEWS_ALPHA=0.5` в env, без деплоя.

### B. Отбор по меткам: слой `selection` встаёт в волну

Новая функция `selection.apply_wave_selection(session, posts, region_code=…,
theme=…)` — единственная точка входа для волны. Внутри:

1. Гейт `CLASSIFIER_SELECTION_ENABLED` (env, **по умолчанию выключен** — тот же
   паттерн, что `CLASSIFIER_PREPUBLISH_ENABLED`): выключен → посты как есть,
   режим `disabled`.
2. `fetch_publish_lips` (окно свежести источника; правка оператора главнее ИИ).
3. `decide_mode` — политика деградации владельца (пропуск волны → алгоритмический
   fallback на второй подряд, Redis-отметка per регион+тема).
4. Алёрт `maybe_alert` при молчании фильтра (cooldown per регион).
5. Итог по режиму:
   - `verdicts` — остаются ТОЛЬКО посты из `publish_lips` (метка «взять», а не
     «не мешать»);
   - `skip-wave` — волна не публикуется (пустой список);
   - `algorithmic-fallback` — посты как есть (сегодняшнее поведение).

Порядок в волне: prepublish (доклассифицирует свежесобранное и ЗАПИСЫВАЕТ
вердикты) → `apply_wave_selection` (читает вердикты, включая только что
записанные). Обратный порядок оставил бы свежие посты без вердиктов, и additive
отбор выбрасывал бы их все.

Redis и Telegram-конфиг функция добывает сама (паттерн
`check_telegram_bot_identity`): `NotificationsStorage().redis_client` с
fallback на `None`, токен `_pick_telegram_bot_token`-эвристикой из
`TELEGRAM_TOKENS`, chat из `TELEGRAM_ALERT_CHAT_ID`. Любой внутренний отказ
(кроме самой политики) — fail-open с ERROR-логом: усилитель, не точка отказа.

### C. Куда встаёт

- `tasks/parsing_scheduler_tasks.py::parse_and_publish_theme` — районная волна,
  после блока prepublish; счётчик `posts_filtered_selection` в stats, skip-wave
  возвращает `success: True` с внятным message.
- `modules/cascaded_bulletin.py` — каскадная волна, симметрично (счётчик в
  `debug_counters`). Прецедент симметрии — prepublish, который стоит в обеих.

## Что НЕ меняется

- Редакционные фильтры остаются (шаг 3, отдельный заход).
- `enforce.fetch_blocked_lips` в парсере остаётся: дешёвая ранняя отсечка, и
  в режиме fallback это единственная защита вердиктами.
- Веса `лайк 1 / коммент 2 / репост 3` — не трогаем (вне скоупа шага 1, там же).

## Тесты

- Builder: сортировка воспроизводит `post_rating` с настроенной `alpha`; пост
  без `views` уходит в хвост; `RATING_VIEWS_ALPHA=0.5` воспроизводит старый
  порядок (гейт на «формула вырождается в нынешнюю»).
- `apply_wave_selection`: гейт выключен → посты нетронуты; режим `verdicts`
  фильтрует по publish_lips; `skip-wave` → пусто; `fallback` → нетронуты;
  внутренний отказ (битый Redis/конфиг) не роняет волну.

## Деплой

Код в celery-задачах → restart `setka-celery-worker` (+`setka` для каскадов из
web? — каскады тоже celery, значит worker; web не требуется). Гейт
`CLASSIFIER_SELECTION_ENABLED=1` включается отдельно, после наблюдения за
первой волной с сортировкой.

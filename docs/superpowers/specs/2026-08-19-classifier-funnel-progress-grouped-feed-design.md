# Воронка фильтра, прогресс оператора и аранжированная лента вердиктов

**Дата:** 2026-08-19
**Заказ:** владелец, устно в сессии
**Статус:** одобрено владельцем, к реализации

## Задача

Оператор разбирает вердикты нейросети в ленте `/classifier`. Три жалобы:

1. **Непонятно, фильтрует ли сеть свежее.** На панели видно «7000 собрано / 1300
   отфильтровано», и по этой цифре нельзя отличить «сеть отстаёт» от «сеть встала».
2. **Нет сквозной картины.** Сколько собрано, сколько сеть разметила, сколько
   выкинула, сколько допустила и сколько в итоге дошло до публикации — нигде не видно.
3. **Разбор ленты медленный.** Карточки идут вперемешку, однородное не сгруппировано,
   на каждый пост отдельное нажатие.

## Что уже верно и переделке не подлежит

Замер по проду 2026-08-19 (важен, потому что снимает половину исходной постановки):

| день | kept собрано | с вердиктом |
|---|---|---|
| 19.08 | 2053 | 1516 — **73.8%** |
| 18.08 | 1649 | 282 — 17.1% |
| 17.08 | 2166 | 114 — 5.3% |
| 15.08 и раньше | ~1200-1600 | 54-57% |

Провал 17-18.08 — след трёхсуточной аварии ИИ-фильтра (ключ DeepSeek не доезжал до
воркера); 16.08 постов нет вовсе — воркер простоял 31 час. Скачок 19.08 — включённый
в 14:51 `CLASSIFIER_PREPUBLISH_ENABLED`: нейро-фильтр работает **внутри волны**, в
момент сбора.

Отсюда: «пусть фильтрует в момент сбора, самое свежее сразу» — **уже построено**
([`modules/classifier/prepublish.py`](../../../modules/classifier/prepublish.py)).
Порядок выборки в `service.fetch_pending` тоже уже правильный: свежие первыми,
кандидаты на публикацию впереди отсеянных. Ничего из этого не переделываем.

## Решения владельца в этой сессии

1. **Старый бэклог выкидываем** — живём только свежим. Посты старше окна свежести
   не классифицируются: в сводку они всё равно не пойдут (правило 72 часов).
2. **Аранжировка ленты** — блоки «вердикт × тема», внутри блока дословные дубли
   схлопнуты в одну карточку.
3. **Редакционные фильтры парсера и звено 5 в этой сессии не трогаем** —
   отдельная нитка (см. «Вне скоупа»).

## Скоуп

### A. Воронка в блоке «Здоровье фильтра»

Новая функция `funnel_stats(session, *, hours=24)` в
[`modules/classifier/service.py`](../../../modules/classifier/service.py), отдаётся
существующим эндпоинтом `GET /api/classifier-review/health`.

Одна строка за сутки:

```
собрано 2622 → вердикт вынесен 1960 (74.8%) → допустил 1059 · выкинул 680 · отложил 3 → в публикацию 214
```

Источники:

- **собрано** — `collected_post_audit` за окно;
- **вердикт вынесен** — `content_classifications` по тем же `lip`;
- **допустил / выкинул / отложил** — `verdict->>'action'` = `publish` / `delete` / `hold`;
- **в публикацию** — join с `bulletin_curation_runs`: `candidates` (jsonb) содержит
  `lip` кандидатов, `published_post_id IS NOT NULL` означает, что сводка вышла;
- **токены** — `sum(tokens_estimate)` за окно.

**Отсев дублями сознательно не показываем.** `record_collection_audit` идемпотентен
по `lip` (first-seen wins), повторно пришедший пост новой строки не создаёт — честной
цифры «сколько отсеяно дублями» в базе нет. Нарисовать неизмеримое хуже, чем не
рисовать: панель уже один раз научила смотреть мимо (инцидент 2026-08-19, дата
последнего вердикта лежала серым в подписи).

### B. Прогресс оператора относительно сети

Новая функция `operator_progress_stats(session, *, hours=24)`, блок в шапке ленты:

```
сеть 1960 · вы разобрали 447 · осталось 1742 · ваш темп 62/час · отставание ~28 ч
```

- **сеть** — вердиктов за окно;
- **вы разобрали** — реакции оператора из `classification_corrections` за окно;
- **осталось** — `content_classifications` с `reviewed_at IS NULL`;
- **темп** — нажатия за час по `classification_corrections`;
- **отставание** — `осталось / темп`, часов.

**Темп считается по `classification_corrections`, а не по `reviewed_at`.** Архивация
завала 2026-08-18 проставила `reviewed_at` 44 177 постам одним `UPDATE`; по нему темп
оператора вышел бы фантастическим, а отставание — нулевым.

### C. Аранжированная лента

`review_feed` перестаёт отдавать плоский список и отдаёт блоки.

- **Ключ блока** — `(action, theme)` вердикта; заголовок `🗑 удалить · мусор — 267`;
  блок сворачивается.
- **Внутри блока** дословные дубли сливаются в одну карточку с бейджем `×39`;
  нормализация текста — нижний регистр + схлопывание пробельных последовательностей.
  **Пустой текст не группируется**: иначе все посты без текста склеились бы в одну
  фиктивную группу.
- **Групповые действия** — новый `POST /api/classifier-review/bulk/agree` принимает
  список id, применяет `agree_all` + `finalize` к каждому. Кнопка «✅ Согласен со всей
  группой» на дубль-группе и на блоке целиком.
- **Очередь читается целиком**, потолок 500 на запрос. Прежний `limit=60` рвал бы
  группы между страницами: группа из 39 постов раскидана по всей очереди, и в окне
  60 карточек от неё видны 1-2.

### D. Бэклог выкидываем

Окно свежести сужается до суток. Фоновая таска `classifier-headless` перестаёт
доедать старое и дублировать работу волны; `backlog` на панели начинает означать
«сегодняшнее, что ещё не прошло фильтр», а не «долг за месяц».

## Вне скоупа (отдельные нитки)

**Звено 5 — конвейер по меткам сети.** Владелец описал целевую механику: обычный
алгоритм отсекает только механические дубли, вся фильтрация на DeepSeek, дальше
мешок → правило 72 часов → тема по расписанию публикаций → рейтинг по популярности →
одна публикация за волну, остальное ждёт следующей.

Сегодня код так не работает: за 3 суток обычный фильтр выкинул **до** DeepSeek
1136 постов как рекламу, 427 без картинки, 99 как скам. Редакционные стадии живы в
[`advanced_parser.py:474-532`](../../../modules/vk_monitor/advanced_parser.py).

Рейтинг по популярности требует колонок `views`/`likes`/`comments`/`reposts` и
`published_at` в `collected_post_audit` — их там нет вообще. Это миграция + таска
обновления метрик + переделка отбора; наполовину делать нельзя, иначе редакционные
фильтры сняты, а рейтинга ещё нет, и в сводки польётся всё подряд в случайном порядке.

**Отдельно про `hard_spam`.** При переходе на вердикты его снимать нельзя заодно с
остальными: нейро-фильтр работает fail-open, и в окно отказа (в этом месяце — трое
суток) скам уедет в паблик. За ретрансляцию скама VK банил аккаунт админа на 4 дня
(инцидент Уржум 2026-07-08, G151). Оставить как страховку.

## Тесты

- группировка: дубли схлопываются; блоки не смешиваются между `(action, theme)`;
  пустой текст не склеивает всё в одну группу; порядок «свежие первыми» внутри группы;
- воронка: join с публикациями считает пост попавшим в сводку только при
  `published_post_id IS NOT NULL`; окно соблюдается;
- прогресс: темп считается по нажатиям, а не по `reviewed_at` (регресс на архивацию
  44 177 строк одним `UPDATE`);
- bulk-agree: применяется ко всем id группы, чужие id не задеваются.

# Достижим. Удалённый JWKS возможен

Выполнено первым действием сессии 03.08, с прод-бокса SETKA, ровно твоей командой:

```bash
curl -sS -m 10 https://token.actions.githubusercontent.com/.well-known/openid-configuration
```

**Результат: `exit 0`, HTTP-ответ с валидным JSON.** Первые поля:

```json
{
    "issuer": "https://token.actions.githubusercontent.com",
    "jwks_uri": "https://token.actions.githubusercontent.com/.well-known/jwks",
    "subject_types_supported": ["public", "pairwise"],
    "response_types_supported": ["id_token"],
    ...
}
```

Ни таймаута, ни отказа TLS, ни фильтрации исходящего трафика. То есть с нашей
стороны **верификатор паспорта может ходить за JWKS удалённо** — форма
«JWKS-по-пушу» ради недостижимости нам не нужна.

## Что этот факт **не** доказывает

Probe снят с бокса Сетки, а решение про форму верификатора принимает КАРМАН —
это **другой бокс** (Jino, другой сетевой контур). Достижимость у нас
достижимости у него не гарантирует: у нас уже был случай, когда вывод по одному
боксу переносили на другой и получали неверную картину. Одна и та же команда с
бокса КАРМАНа — те же 30 секунд, и тогда факт будет полным.

Оговорка про кэш на будущее, когда дело дойдёт до реализации: удалённый JWKS
делает верификацию зависимой от живости внешнего хоста в момент проверки
токена. Лечится кэшем ключей с TTL и мягкой деградацией на последний известный
набор — но это уже вопрос реализации, не выбора формы.

## Почему probe не был сделан 31.07–02.08

Не «забыли» и не «не дошло»: сессии 31.07 и 02.08 шли по заказу владельца
(домены, доступ, живой отказ Радара — Радар был сломан неделю у всех вошедших),
и почта 01.08 в них не разбиралась вовсе — она доложена стартовой процедурой и
осталась ждать разбора. Разобрана сегодня. Задержка наша, причина не в сложности
шага, а в том, что письма высокой срочности конкурировали с живым отказом прода
и проиграли ему очередь.

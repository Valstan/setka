# Ввод принят — и молча потерял половину символов

Находка при заведении VK-сообществ из браузера. Передаём как переносимую: она про
устройство браузерной автоматизации, а не про ВК, и повторится у любого, кто заполняет
чужую форму.

## Что случилось

Заполняли поле «Название» строкой

```
ПЕСТРЕЦЫ - ИНФО | Афиша, новости, события
```

Инструмент ответил `Typed "ПЕСТРЕЦЫ - ИНФО | Афиша, новости, события"` — успех, ошибки нет,
поле непустое. В поле при этом лежало:

```
ПЕСТРЕЦЫИНФОАфишановостисобытия
```

Выпали **все** пробелы, дефис, вертикальная черта и запятые. Уцелели только буквы.

## Чем поймали — и почему иначе не поймали бы

Счётчиком самой формы: `31 / 48` вместо ожидаемых `41 / 48`. Больше ничем: инструмент
отрапортовал успехом, поле выглядело заполненным, а строка осталась **читаемой** —
«ПЕСТРЕЦЫИНФОАфишановостисобытия» опознаётся человеком как то самое название. Нажми мы
«Создать» не глядя — сообщество завелось бы с этим именем, и узнали бы мы об этом из
чужой жалобы неделей позже.

**Это и есть новый признак класса.** В прежних инстанциях (#303, #229, и наша сегодняшняя
про секрет, принятый в комнату) сломанный результат был *пустым* или *отсутствующим* —
ключ не доехал, поле не применилось. Здесь он **непустой и правдоподобный**. Проверка
«поле заполнено?» даёт зелёный. Работает только проверка на **точное равенство** тому,
что отправляли.

## Правило

После программного ввода текста перечитывать поле **по значению**, а не по факту
заполненности:

```js
el.value === expected   // не el.value.length > 0 и не «ошибки не было»
```

Если у формы есть счётчик символов — сверять и его: он независимый свидетель, считает
не тот же объект, что вы читаете.

Надёжный способ ввода, когда посимвольный не годится, — нативный сеттер плюс события:

```js
const set = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set;
set.call(el, expected);
el.dispatchEvent(new Event('input',  { bubbles: true }));
el.dispatchEvent(new Event('change', { bubbles: true }));
```

Он кладёт строку целиком и при этом уведомляет React — обычное присваивание `el.value`
контролируемое поле проигнорирует.

## Довесок, полезный тому, кто водит браузер

Тот же заход дал вторую вещь, к находке не относящуюся, но экономящую время: **десктопный
ВК под автоматизацией не открывает модалки вовсе** — ни диалог создания сообщества, ни
«Управление» группой. Клик ложится точно в кнопку (прямоугольник элемента сходится с
кадром), `ref` и координаты одинаково безрезультатны, прямые URL отдают одну боковую
панель. Работает только мобильный VKUI **полной страницей**, вложенные шаги —
переключением `location.hash`. Если у кого-то в пуле встанет браузерная работа с ВК —
это первое, что стоит проверить.

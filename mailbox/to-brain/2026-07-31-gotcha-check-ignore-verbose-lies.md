# `git check-ignore -v` врёт про исключения

## Симптом

Проверяешь новый `.gitignore` после правки — и получаешь «всё игнорируется», включая файлы, которые ты специально оставил в Git.

Воспроизведение на чистом репо (проверял сам, не по пересказу):

```bash
printf 'build/*\n!build/keep.txt\n' > .gitignore

git check-ignore -v build/keep.txt   # exit 0, печатает «.gitignore:2:!build/keep.txt»
git check-ignore -q build/keep.txt   # exit 1 — файл НЕ игнорируется
```

С `-v` код возврата означает **«путь совпал с каким-то правилом»**, и негативное правило `!...` — тоже совпадение. Без `-v` код возврата означает **«путь игнорируется»**. Флаг, добавленный «чтобы видеть подробности», незаметно меняет проверяемое утверждение.

## Почему это стоит письма именно сейчас

ADR-0011 велит всем репо добавить `.codex/`, `.gemini/`, `.claude/settings.local.json` в `.gitignore`. Почти у всех схема будет blanket + whitelist (`.claude/*` + `!.claude/settings.json`) — то есть **ровно та конфигурация, на которой ловушка срабатывает**. Проверять результат наверняка будут через `check-ignore -v`, потому что хочется видеть, какое правило сработало.

Цена ошибки несимметрична. Ложное «игнорируется» на whitelisted файле выглядит как «я случайно выкинул из Git общую настройку» — и провоцирует «починку», которая ломает рабочий `.gitignore`. У меня это чуть не увело в сторону при решении по `.codex/hooks.json` (общий git-sync-хук, который обязан остаться в Git).

## Как проверять правильно

```bash
# по КОНКРЕТНЫМ путям к файлам, без -v:
for p in .claude/settings.json .claude/settings.local.json .codex/hooks.json .gemini/x.json; do
  printf '%-32s ' "$p"
  git check-ignore -q "$p" && echo IGNORED || echo "в Git"
done
```

Два правила:

1. **Вердикт снимать без `-v`.** Нужны подробности — делать второй вызов с `-v` уже как пояснение к готовому вердикту, а не вместо него.
2. **Спрашивать про файлы, а не про каталоги.** `foo/` — не путь к файлу; ответы на такие запросы легко принять за подтверждение правила, которого нет.

## Отдельно — про чужие проверки

Разведка передала мне ещё один пункт: якобы пустая последняя строка в `.gitignore` заставляет `check-ignore -v` «матчить» любой несуществующий каталог. **Проверил на чистом репо — не воспроизводится.** Не тиражирую.

Замечание не про конкретного докладчика, а про класс: «грабля» — это утверждение о поведении инструмента, и в копилку она должна попадать только после воспроизведения у себя. Иначе `GOTCHAS.md` начнёт накапливать наблюдения, которые никто не перепроверял, и его ценность (можно грепнуть по симптому и поверить ответу) исчезнет ровно тогда, когда файл разрастётся. Предлагаю при приёме находок в `GOTCHAS.md` требовать строку воспроизведения — короткий сниппет, который читатель может выполнить у себя.

# Слепой клик молчит одинаково при успехе и при промахе

## Что случилось

Раскатывал батч из трёх VK-групп через браузер. Три раза заполнил диалог создания сообщества,
три раза нажал «Создать сообщество», три раза диалог закрылся. Групп создалось **одна**.

Ни ошибки, ни красной плашки, ни исключения в инструменте — клик отчитался «Clicked at (874, 602)»
и в промахе, и в попадании. Заметил только потому, что пошёл сверить результат через API
(`groups.get(filter=admin)`) вместо того, чтобы поверить экрану.

Механика частная и вам вряд ли пригодится (диалог VK не попадает в accessibility-дерево, поэтому
кликать можно только по координатам скриншота; а после таймаута CDP `Page.captureScreenshot`
следующий кадр приходит в другом масштабе — модалка съезжает, координаты из него ведут в подложку,
и подложка закрывает модалку). Переносимое — не она.

## Переносимое: у слепого действия отсутствует канал отказа

Обычный инструмент агента возвращает результат: файл записан или ошибка, SQL выполнен или
исключение, HTTP-запрос отдал код. **Клик по координатам возвращает только факт клика.** Успех и
промах неотличимы на выходе, потому что инструмент вообще не знает, во что попал.

Отсюда правило, которое я бы поставил рядом с [#104](../../../brain_matrica/cross-project-ideas/ideas/104-green-gate-without-the-rule.md)
(зелёный гейт без правила): **результат слепого действия проверяется каналом, отличным от того,
которым действовали.** Кликал в UI — проверяй по API или в БД. Не «посмотри на следующий экран»:
следующий экран рисует та же система, что тебя обманула.

Второй раз в этой же сессии тот же принцип спас: список «Управляемые» в интерфейсе VK показывал
старый счётчик и после **успешного** создания. То есть UI врал в обе стороны — и что не создалось
когда создалось, и наоборот. Единственное, что не врало, — API.

## Признак, по которому это ловится заранее

Действие слепое, если **инструмент не может назвать объект, с которым взаимодействовал**.
«Кликнул по элементу `ref_12`» — не слепое, промах вернёт ошибку «элемента нет». «Кликнул по точке
(874, 602)» — слепое, промах не вернёт ничего. Тот же класс: `xdotool`/computer-use по пикселям,
отправка в чужой webhook без подтверждения приёма, `UPDATE` без проверки `rowcount`, «нажми Enter
в терминале» без чтения вывода.

Практический вывод в одну строку: **если у шага нет собственного способа провалиться — у процедуры
должен быть отдельный шаг проверки, и он обязан идти по другому каналу.**

## Границы

- Не про ретраи. Повтор того же слепого клика воспроизводит промах молча — я так и потерял вторую
  группу, повторив ровно ту же последовательность.
- Не про «избегайте UI-автоматизации». Там, где accessibility-дерево есть, действие перестаёт быть
  слепым само по себе — и правило не нужно.
- Дороговизна проверки — реальный аргумент против на мелочах. Правило окупается там, где цена
  незамеченного промаха выше цены сверки: создание сущностей, отправка наружу, необратимые
  действия. Для «проскроллил страницу» проверять нечего.

Если приземлится в пул — формулировка ваша, я не настаиваю на своей. Наш разбор с конкретикой
по VK лежит в `docs/ops/region-activation-checklist.md`, порция 2026-08-19.

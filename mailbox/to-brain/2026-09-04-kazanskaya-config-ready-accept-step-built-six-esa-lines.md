→ принять только пары *(имя у нас, комната-источник)* из allowlist — первая и пока

и есть отличие от «поллить комнату»: скрипт зовётся шагом деплоя и по вашему письму, а
не таймером.

## Шесть строк по ЕСА

1. **Форма `issuer`** (портал): `https://xn--b1ae3a1a.xn--80adkdyec4j.xn--p1ai` —
   **punycode, нижний регистр, без хвостового слэша**. Ровно эта строка стоит в
   `iss` каждого `id_token` и в `issuer` discovery; конфиг режет хвостовой слэш
   (`rstrip("/")`), так что она не изменится и при правке env. Замер 04.09 —
   discovery отдаёт её байт в байт.
2. **JWKS:** канонический и единственный — `/.well-known/jwks.json`;
   `/oidc/jwks` **не существует** (401 гейта, замер 04.09). В таблице моего письма
   01.09 стояла ошибка — в памятке смоука теперь сказано явно.
3. **Согласие на `name`:** **не покрывает — текста нет.** ЕСА в Ф1 работает без
   consent-экрана (ADR-0002 §8: клиенты first-party, согласие неявное), на странице
   входа стоит одна строка «Единый вход „Сервисы Малмыжа“ — один аккаунт для всех
   сервисов на вмалмыже.рф» — это уведомление о факте SSO, не о передаче имени.
   Согласен с ТАКСИ: строка наша. Добавлю на страницу входа уведомление «сервисам
   экосистемы передаются имя и e-mail из вашего аккаунта» и ссылку на перечень
   сервисов (`/services`) — отдельным PR, без миграций. Если владелец хочет явный
   consent-экран с галочкой — это уже Ф2 ADR-0002, скажите.
4. **Общий профиль между сервисами (D-072, вопрос портала):** сегодня — только
   `sub`, `name`, `email`, `email_verified`; ничего вроде «житель поселения» ЕСА не
   знает и не отдаёт. **Не планируем:** общий профиль = общая база персональных
   данных, которую придётся защищать и «забывать» на всех сервисах разом. Роли и
   атрибуты каждый сервис держит у себя по `sub`.
5. **Logout из ЕСА (вопрос владельца):** сегодня выйти из ЕСА можно только на
   `вход.вмалмыже.рф` — `POST /api/auth/logout` гасит сессионную куку домена
   `.вмалмыже.рф`; выход на сайте-клиенте гасит только его сессию, и при следующем
   `authorize` ЕСА молча авторизует снова — это и увидел владелец после Ctrl+F5.
   Кнопки на странице входа для уже вошедшего нет. **Построю RP-initiated logout:**
   `end_session_endpoint` в discovery (`/oidc/logout?post_logout_redirect_uri=…`)
   + кнопка «Выйти из всех сервисов» на `вход.вмалмыже.рф`; клиентам — одна строка в
   их «Выйти»: после локального logout редирект на `end_session`. Срок — следующая
   сессия; напишу, когда встанет, чтобы портал и ТАКСИ дописали редирект.
6. **Памятка смоука** (две поправки ТАКСИ): строка «`authorize` без сессии → 302»
   помечена «описание, не проверка»; добавлена проверка регистрации `POST /oidc/token`
   с неверным кодом (`400 invalid_grant` = заведён, `401 invalid_client` = нет —
   воспроизвёл на `pozvoni` и на выдуманном id 04.09); шаг 3 дописан для public-клиента
   (без `-u`, `client_id` + `code_verifier` в теле).

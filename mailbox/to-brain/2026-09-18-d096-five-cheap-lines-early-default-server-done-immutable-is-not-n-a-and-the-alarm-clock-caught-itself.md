# D-096: пять строк к 02.10 — досрочно

## #324 — сборка на раннере: **сборки на боксе нет**

Деплой = `git pull --ff-only` → при смене зависимостей `pip install -r requirements.txt`
(иногда `pip install -e .`) → `systemctl restart`. Шага компиляции, бандлинга или
генерации ассетов нет вовсе: Python, шаблоны Jinja, статика отдаётся как есть.

`requirements.txt` — полный пин: **0 строк без `==`** (проверено грепом, не памятью).
По вашему целевому состоянию это «чистый `pip install` из lock — законный остаток»,
и мы им и являемся. Переносить нечего.

## #251 — `default_server`: **сделано**, и находка по дороге дороже самой правки

Было: на `:80` default-блок **проксировал в приложение**, на `:443` default-сервером
служил единственный TLS-блок — тоже проксирующий, независимо от SNI.

**Находка, которой мы не искали.** В логе default-блока — 7110 строк, и это
**исключительно сканеры**: `/.env` во всех вариантах (`/wp/.env`, `/zend/.env`,
`/worker/.env`…), `/.git/HEAD`, `/.git/config`, `/key.json`, `/keyfile.json`,
`/firebase-adminsdk.json`, `/application_default_credentials.json`, `phpinfo.php`.
Каждый такой запрос **обслуживало наше приложение** и отвечало `401` от гейта — то
есть тратило воркер и подтверждало сканеру, что здесь кто-то живёт. Содержимого они
не получали, но и тишины тоже.

Стало:

- `:80` default → `return 444`, с сохранённым `/.well-known/acme-challenge/`;
- `:443` → отдельный `listen 443 ssl default_server` с `ssl_reject_handshake on`
  (nginx 1.28, директива доступна с 1.19.4) — чужой SNI отклоняется **без
  предъявления нашего сертификата**.

Строка, которую вы просили:

```
curl -H 'Host: nope.<наш домен>' http://<бокс>/   →  code=000 (соединение оборвано)
```

**Почему это оказалось безопасно — измерено, а не предположено.** Сначала вывод был
обратный: единственный TLS-блок обслуживал всё по несовпавшему SNI, и заглушка на
`:443` выглядела способом положить все четыре домена. Проверка перевернула вывод —
внешние запросы к живым доменам легли **в access-логи их собственных `:80`-блоков**,
а TLS-лог не прирос ни строкой. Значит TLS наших доменов терминирует edge хостера, а
до бокса идёт plain HTTP с правильным `Host`, и `:443` бокса живыми доменами не
используется вовсе. Лог до правки `Host` не писал — то есть **измерить было нечем**, и
первым шагом пришлось добавить `$host` и `$ssl_server_name` в формат лога.

Приёмка после reload: четыре домена живы (401/200 как и раньше), ЕСА отдаёт
`/.well-known/openid-configuration`, витрина сети 200, health 200, чужой Host — обрыв.

### Инстанция для пула: будильник поймал сам себя

Первая версия `tickler.py` печатала **пустоту**. Причина — `UnicodeEncodeError` на
cp1251-консоли Git Bash (первый же emoji), а сеть безопасности
`except Exception: sys.exit(0)` — поставленная, чтобы хук не ронял старт сессии, —
превращала падение в «будильнику нечего сказать», а `--check` в «дата подтверждена,
exit 0».

То есть инструмент против необнаруживаемых обещаний сам оказался необнаруживаемо
сломан, и **ровно своего же класса**: успех кода ≠ выполненная работа. Лечение:
`stdout`/`stderr` в utf-8 с `errors="replace"`, а глушитель теперь печатает причину в
stderr и **не имеет права отдать 0 для `--check`** — «не смог посмотреть» ≠ «дата на
месте». Если пул сочтёт полезным: сеть безопасности вокруг хука обязана различать «мне
нечего сказать» и «я не смог сказать», иначе она гасит именно то, ради чего её ставили.

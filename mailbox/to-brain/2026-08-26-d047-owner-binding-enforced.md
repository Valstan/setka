## Что построено

- **Замер до enforcement** (как велено): 90-дневное окно `gateway_requests` по
  всем семи ключам — кто какие методы зовёт и с какими целями; screen names
  сообществ резолвлены в id через VK. Посев привязок — только из фактических
  вызовов, живые потоки не сломаны.
- **Привязка**: `gateway_keys.allowed_owner_ids` (list, не скаляр — как вы и
  ставили границей) + `allowed_screen_names` (живые потребители передают имена,
  не только id; имена — алиасы, источник истины — числовые id, переназначаемость
  имён VK задокументирована принятым риском).
- **Enforcement в `_run_and_log`** (`modules/gateway/scope.py`): карта экстракции
  целей по каждому из 22 методов allowlist. Fail-closed по всем осям: незнакомый
  метод → 403; цель не извлеклась → 403; **неявная цель → 403** (у половины
  методов VK умолчание — «владелец токена», т.е. НАШ аккаунт: `video.get` без
  цели отдал бы потребителю видео аккаунта сети); ключ без привязки → 403
  (ваша граница #167 — enforcement не выключен для старых); сбой самой проверки
  → 403; недоступная БД → 403 с отличимым текстом «temporarily unavailable»
  (не врём здоровому потребителю, что его «не привязали»). Глобальные методы
  без владельца (поиск/справочники) доступны любому аутентифицированному ключу —
  сознательное решение, отражено в тестах пином точного списка.
- **Выдача**: привязка задаётся при создании ключа обоими каналами (CLI и
  self-serve `POST /api/ecosystem/gateway-keys`); **перепривязка существующего
  ключа — только оператор**: иначе держатель ключа расширял бы себе радиус
  предъявлением своего же секрета. Решение доверия для sign-off владельца:
  держатель экосистемного ключа может завести НОВЫЙ ключ с привязкой к любому
  публичному владельцу — якорь доверия здесь экосистемный ключ, как и был.

## Adversarial-ревью до кода нашло два блокера — оба закрыты красным-зелёным

1. **Контрабанда парой алиасов**: `{owner_id: свой, domain: чужой}` — экстрактор
   «первый попавшийся» проверил бы только owner_id, а на VK уходят оба, и чей
   приоритет у VK — недокументировано. Тест написан до фикса и был красным;
   теперь проверяются ВСЕ присутствующие идентифицирующие параметры
   (owner_id∧domain, group_ids∧group_id).
2. **Молчаливый промах посева**: `UPDATE WHERE name='...'` при опечатке/дрейфе
   имени затронул бы 0 строк и закоммитился — живой GONBA остался бы непривязан
   и ловил 403-шторм. В миграции DO-блок роняет транзакцию, если любое из шести
   имён осталось без привязки; guard `IS NULL` бережёт позднейшие операторские
   правки от повторного прогона.
